## Что сделать

Файл `decks/comprehensive/part_X.js` (X — буква твоей части):

```js
const { C, ACCENTS, CHART_COLORS, columns, IN, PT } = require('../../lib/akrikhin');
const MEDIA = require('path').join(__dirname, '..', '..', 'work', 'comprehensive', 'src', 'media');

module.exports = {
  17: (d) => {
    const s = d.slide({ title: '...', subtitle: '...' });
    // ...
  },
  18: (d) => { /* ... */ },
};
```

Ключи — номера слайдов черновика. Каждая функция добавляет ровно один слайд через `d.slide(...)`.

Сборка и проверка (повторять, пока не станет чисто):

```bash
node decks/comprehensive/run_part.js part_X          # → out/comp_part_X.pptx, печатает предупреждения
python3 tools/validate_pptx.py out/comp_part_X.pptx
tools/render.sh out/comp_part_X.pptx                 # → out/render/comp_part_X/slide-N.png
```

Смотри **каждый** отрендеренный PNG (Read) и сравнивай с исходником: переполнения, наложения, обрезанный текст, разорванные слова, пропавший контент, неровные отступы. Предупреждения сборки к концу должны быть устранены.

## Правила по содержанию

- Текст — из черновика, дословно. Можно: исправить явные опечатки и слипшиеся слова, убрать лишние пробелы, перевести заголовок из КАПСА в обычный регистр (аббревиатуры и термины оставить: CJM, AI, OMD Voice, DOOH, SEO, GEO/AEO, ORM, CTV, OLV, DSP, DMP, KPI, ВНТ, Tier-2, Paid Search и т. п.).
- Нельзя: перефразировать, сокращать по смыслу, выкидывать пункты, придумывать тексты и цифры. Если контент физически не влезает даже на минимальных кеглях — оставь всё, перекомпонуй, а в отчёте опиши проблему.
- Длинный заголовок черновика с отдельной строкой-пояснением под ним → `d.slide({ title, subtitle })`. Заголовок без пояснения → `d.slide({ title })` (до 2 строк).
- Нижняя плашка черновика («ПРИНЦИП 2027 | текст», «РЕЗУЛЬТАТ», «ВЛИЯНИЕ НА БИЗНЕС», «PHARM-SAFE», «ВЫВОД», «РЕЗУЛЬТАТ AI» …) → `s.principle({ label, text, icon })` с меткой из черновика. Синяя плашка черновика («ЕДИНАЯ МОДЕЛЬ», формула-цепочка) → `s.principle({ color: C.blue, ... })` или `s.formula(...)`.
- Строка-подпись под плашкой («Human in the loop: …», «Роль в Comprehensive: …») и источники → `s.footnote(...)` (y ≈ 1030).
- Вертикальную надпись «GOLDEN RULES 2027» сбоку (слайды 45–48) не переносим — это метка раздела; упомяни в отчёте.
- Жёлтые выделения текста в черновике — это пометки автора: текст переносим обычным, в отчёте перечисли, что было выделено.
- Логотип «Акрихин 90 лет», номера страниц, полосы-подчёркивания под заголовком — не переносим (у нас знак «a» в шапке).

## Правила по дизайну

- Строго по `DESIGN.md`: поля 58, шапка через `d.slide`, контент 221…905, плашка 935…1019, сноска от 1030.
- Компоненты библиотеки в приоритете. Нет нужного — локальный хелпер в своём файле поверх `s.s` (сырой слайд pptxgenjs), `s.deck.pres.ShapeType`, `IN`/`PT`, но в стиле системы (радиусы 25/15, обводка `C.line`, цвета из `C`).
- Кегли: основной текст ≥ 16 px; вторичные пояснения на плотных слайдах ≥ 14 px; сноски и подписи графиков ≥ 13 px. Для текстов переменной длины — `fit: true` + `minSize`.
- Одинаковые элементы соседних колонок — на одной высоте; отступы ровные.
- Цвета номеров/колонок — `ACCENTS` по порядку (или как в эталоне фигмы).
- Иконки — белые линейные в плитках/плашках: фирменные (`bulb`, `target`, `checklist`, `flow`) или Tabler `tb:TbИмя` (проверь, что имя существует в react-icons/tb).
- Графики — только `s.chart` с данными из json, по правилам раздела «Графики» в DESIGN.md (одна ось!). График в карточке, над ним КАПС-метка, источник — сноской.
- Картинки — `s.image(path.join(MEDIA, 'img_….png'), { x, y, w, h })` с сохранением пропорций.

## Ограничения
