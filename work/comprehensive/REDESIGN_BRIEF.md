# Бриф: новые варианты содержательных слайдов деки Comprehensive 2027 (аудит)

Рабочая папка — корень проекта (папка с `AGENTS.md`); пути ниже — от неё.

Дека уже собрана в дизайн-системе Акрихин × OMD. Роман сказал, что последние варианты слайдов с данными (2–15) получились хорошо, и попросил пересмотреть остальные. По итогам аудита для 9 слайдов нужно нарисовать **новый вариант** — он ляжет в деку рядом с исходным, Роман выберет.

## Что прочитать

1. `DESIGN.md` — целиком (палитра, типографика, сетка, компоненты, «Приёмы для слайдов с данными»).
2. `lib/akrikhin.js` — API (не редактировать). Полезное: `d.slide({title, subtitle})`, `s.text/box/card/badge/numberedCard/stat/tile/pill/label/heading/steps/checks/arrow/chevron/principle/formula/icon/circle/seg/image/chart/table/footnote/notes`; `steps`/`checks` умеют `pitch: 'auto'`; `icon(name, {circle: C.blue})` — иконка в кружке; `s.chart(..., {plot,min,max})` возвращает преобразование «данные → px».
3. `decks/variants/common.js` и образцы уровня качества — код `decks/variants/v06_09.js`, `v10_12.js`, `v13_15.js` и их рендеры `out/render/variants_all/slide-NN.png` (напр. 18–40). **Это планка**: ясная главная точка, крупные цифры, подписи на графике, воздух, ровная сетка.
4. По своему слайду N:
   - как он выглядит сейчас: `out/render/final/slide-(N+14).png` (в текущей деке номер сдвинут на 14);
   - **тексты — из кода текущей версии** в `decks/comprehensive/part_*.js` (ключ = N): там они уже вычищены (опечатки, тире). Сверка с черновиком: `work/comprehensive/src/slide-NN.png` / `.json`;
   - картинки — `work/comprehensive/src/media/`.

## Что сделать

Файл `decks/redesign/rNN_MM.js` (имя — в задаче):

```js
const path = require('path');
const { C, ACCENTS, columns, IN, PT, chartMap } = require('../../lib/akrikhin');
const V = require('../variants/common');   // TOP, BOT, MUTED, GRID, fmt, pct, statTile, numMark, legend ...
module.exports = {
  25: [(d) => { const s = d.slide({ title: '...', subtitle: '...' }); /* ... */ s.notes('Слайд 25 · новый вариант: <приём>'); }],
};
```

Каждая функция добавляет один слайд (для 37 — две функции, два слайда). **В конце каждого слайда — `s.notes('Слайд N · новый вариант: …')`**, на самом слайде служебных подписей нет.

Проверка (повторять до чистоты):
```bash
node decks/redesign/run.js rNN_MM          # исходный слайд + новый вариант парами → out/redesign_rNN_MM.pptx
python3 tools/validate_pptx.py out/redesign_rNN_MM.pptx
tools/render.sh out/redesign_rNN_MM.pptx   # → out/render/redesign_rNN_MM/slide-N.png
```
Смотри каждый PNG свежим взглядом и **сравнивай новый вариант с исходным**: новый должен быть заметно лучше — читается за 3–5 секунд, есть одна главная точка, текст крупнее, нет пустых дыр и тесноты. Не останавливайся на первом рендере.

## Правила

- **Текст — дословно** из текущей версии (можно переставлять, разбивать на заголовок/пояснение, выделять жирным/цветом ключевые слова). Нельзя перефразировать, выкидывать пункты, придумывать новые утверждения. Короткие служебные подписи-связки («2026», «2027», «Было / Стало», «→ см. следующий слайд») — можно.
- Производные цифры — только посчитанные из данных слайда, с пометкой «расчёт OMD» в сноске.
- Шапка: тот же заголовок и подзаголовок, что сейчас. Нижняя плашка (`principle`/`formula`) — сохранить с тем же текстом, место 935…1019 (можно шире: `w` до 1804).
- Контент 221…905 (над плашкой), поля 58. Основной текст ≥ 16 px, ключевые формулировки ≥ 20, большие цифры 54–72. Мелкие пояснения ≥ 14 — только для вторичного.
- Меньше одинаковых по весу коробок. Иерархия: главное — крупно и в цвете, второстепенное — спокойно.
- Цвета — только из `C`; акцент один (обычно малиновый), остальное синие оттенки и `MUTED`.

## Концепции

### 25 · «Активация сегментов: от AI DMP к прямым интеграциям с платформами (DSPs)» — `part_d.js`
Было/стало. Слева (≈⅓, приглушённо): «2026 · Единое DMP-решение» — вертикальная цепочка AI CJM → DMP → Все платформы и «Ограничения» с крестиками. Справа (≈⅔, ярко): «2027 · Прямые интеграции с DSP» — схема-цикл из трёх узлов: OMD Voice (техническая карта сегмента) → платформа/DSP (сборка на стороне платформы) → размер возвращается в планирование ↺ (стрелки по кругу или треугольником), подписи узлов — тексты трёх шагов. Под схемой — «Что получаем»: «Экономия 30%+» большой цифрой + 2 пункта. Внизу узкой полосой — «Два контура» (прямые интеграции / внешние AI-сегменты) и «People vs IDs». Плашка «Принцип 2027».

### 30 · «Paid Search Playbook 2027: от закупки трафика к управлению спросом и инвестициями» — `part_e.js`
Три роли — три крупные колонки с иконками (Protect — щит, Grow — вход/рост, Convert — корзина): название, задача, пояснение, и **внизу каждой колонки — её влияние на бизнес** (Protect → «Меньше потерь», Grow → «Выше рост», Convert → «Больше конверсий» — сопоставь по смыслу текстов). Под колонками — полоса «Синхронизация SEO+GEO/AEO+Paid Search: Q4 2026 → полная трансформация 2027» и схема ежемесячного decision cycle: 4 сигнала (ёмкость спроса, конкурентное давление, экономика конверсии, покрытие SEO и GEO/AEO) сходятся стрелками в «Решение: инвестировать / поддержать / снизить, перераспределить»; «фиксированный бюджет/мес → динамическое распределение инвестиций» — подписью. Плашка.
