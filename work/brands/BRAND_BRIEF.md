# Бриф: пересборка деки стратегии бренда Акрихин в единой дизайн-системе

Рабочая папка — корень проекта (папка с `AGENTS.md`); все пути — от неё.

Есть серия дек «стратегия бренда на 2027» (по брендам Акрихин, от OMD). Деки собраны разными людьми в разных стилях. Задача — привести каждую к **красивому единому виду** в нашей дизайн-системе Акрихин × OMD, с сохранением всего контента. Потом из той же сборки автоматически делается **английская версия** (тексты подменяются переводом при сборке, вёрстка пересчитывается под английский).

Текущий бренд, исходник и твои слайды — в задаче от координатора.

## Что прочитать

1. `DESIGN.md` — целиком: палитра, типографика, сетка, компоненты, «Графики», «Приёмы для слайдов с данными», «Правила вёрстки».
2. `lib/akrikhin.js` — API (не редактировать). Методы класса Slide: `text, bullets, card, box, badge, numberedCard, stat, tile, pill, label, heading, steps, checks, arrow, chevron, principle, formula, circle, chart, table, seg, hline/vline, icon, image, footnote, notes`. `steps`/`checks` умеют `pitch: 'auto'`; `icon(name, {circle: C.blue})`; `s.chart(kind, series, {plot,min,max})` возвращает преобразование «данные → px».
3. **Планка качества** — слайды, которые заказчик уже одобрил:
   - `decks/variants/v*.js` и их рендеры `out/render/variants_all/slide-NN.png` (слайды с данными: один акцент, подписи на графике, большие цифры справа);
   - `decks/redesign/r*.js` и рендеры `out/render/redesign_*/slide-*.png` (текстовые слайды: ясная главная точка, мало одинаковых коробок, крупный текст);
   - `decks/comprehensive/part_*.js` — много готовых раскладок (колонки, матрицы, таймлайны, цикл, «было → стало»).
4. По каждому своему слайду N исходника:
   - `work/brands/<brand>/src/slide-NN.png` — как он выглядит сейчас (Read);
   - `work/brands/<brand>/src/slide-NN.txt` — все тексты с координатами (px при ширине 1920; кегли исходника не копируем), данные графиков и таблиц;
   - `work/brands/<brand>/src/slide-NN.json` — то же в JSON (данные графиков брать отсюда);
   - `work/brands/<brand>/src/media/` — картинки слайда (имена — в `.txt`, строки IMAGE).

## Что сделать

Файл `decks/brands/<brand>/part_X.js` (буква — в задаче):

```js
const path = require('path');
const { C, ACCENTS, CHART_COLORS, columns, IN, PT, chartMap, textWidth, fitSize, countLines, typo } = require('../../../lib/akrikhin');
const V = require('../../variants/common');               // TOP, BOT, MUTED, GRID, fmt, pct, statTile, numMark, legend, yearAxis, gridY
const SRC = path.join(__dirname, '..', '..', '..', 'work', 'brands', '<brand>', 'src');
const MEDIA = path.join(SRC, 'media');

module.exports = {
  3: (d) => { const s = d.slide({ title: '...', subtitle: '...' }); /* ... */ },
};
```

Ключ — номер слайда исходника; функция добавляет один (или, если слайд правда не помещается, два) слайда.

Проверка (повторять до чистоты):
```bash
node decks/brands/build.js <brand> --part part_X        # → out/brand_<brand>_part_X.pptx, печатает предупреждения
python3 tools/validate_pptx.py out/brand_<brand>_part_X.pptx
tools/render.sh out/brand_<brand>_part_X.pptx           # → out/render/brand_<brand>_part_X/slide-N.png
```
Смотри **каждый** PNG свежим взглядом, сравнивай с исходником: весь ли контент на месте, читается ли главная мысль, нет ли переполнений, наложений, обрезанного текста, кривых отступов. Доводи, пока не будет на уровне планки.

## Единый вид (обязательно)

- Шапка — только через `d.slide({ title, subtitle })`: одинаковая синяя шапка со знаком «a» на всех слайдах. Логотип «Акрихин 90 лет», разные полосы-подчёркивания, номера страниц исходника — не переносим.
- Обложка исходника → `d.cover(...)` (заголовок — название бренда / темы как в исходнике; подпись «Strategic approach 2027 by OMD» — как подзаголовок-строка или kicker). Разделители разделов → `d.divider(...)`.
- Контент 221…905, нижняя плашка-вывод `s.principle` / `s.formula` на 935…1019, сноски/источники от 1030. Если в исходнике нет вывода — плашку не придумываем, контент может занять 221…1005.
- Главная мысль слайда — крупно и в акценте; одинаковых коробок с мелким текстом — меньше. Основной текст ≥ 16 px (лучше 18), вторичный ≥ 14, сноски ≥ 13.
- Графики — живые `s.chart` по правилам DESIGN.md (одна ось! вторую ось исходника — подписями или отдельным графиком), данные из json. Серии с технарскими именами («acriol, mln rur») — переименовать по-человечески («Акриол Про, млн ₽»). Даты-числа Excel (46020 = 2026-01-…) — перевести в даты.
- Таблицы исходника — нативная `s.table` или своя раскладка, если так читаемее.
- Картинки (креативы, фото, скриншоты) — `s.image(path.join(MEDIA, '…'), {x,y,w,h})` с сохранением пропорций (размеры — по файлу). Картинка-подложка во весь слайд (скриншот старого дизайна) — не переносим, берём живой текст.

## Контент

- **Весь контент сохраняем**: каждый пункт, цифру, подпись, источник. Можно: переставлять, объединять повторы, разбивать на заголовок/пояснение, выделять ключевые слова, исправлять опечатки и типографику (« - » → « — », кавычки «»), переводить КАПС в обычный регистр (кроме аббревиатур). Нельзя: перефразировать по смыслу, выкидывать пункты, придумывать цифры и выводы. Производные цифры — только посчитанные из данных слайда, с пометкой «расчёт OMD» в сноске.
- Ошибки исходника (несовпадение цифр, чужой бренд в подписи, битые даты) — **не молча исправлять**, а оставить как есть или исправить очевидное и обязательно описать в отчёте.

## Важно для английской версии (сборка та же, тексты подменяются)

- Каждая фраза — **одной строкой целиком** в вызове (`s.text('Целое предложение…')`), не склеивать русские куски шаблонами (`${n} регионов`) — переводчику нужен контекст, а словарь ищет строку целиком. Числа внутри строки — нормально.
- Не завязывай геометрию на точную длину русского текста: для заголовков/плашек/подписей в ограниченных местах — `fit: true` + `minSize` / `maxLines`; высоту следующего блока бери из возвращаемой высоты `s.text(...)`, а не константой, где текст может стать длиннее. Английский обычно короче, но КАПС-метки бывают длиннее — оставляй запас ~15% в узких местах.
- Разметка `**жирный**` / `[[акцент]]` переводчиком сохраняется — ей можно пользоваться.

## Грабли (собраны на 7 деках серии)

- Символов U+2060 (word joiner) и U+2011 (неразрывный дефис) нет в Tahoma — в PowerPoint они рисуются квадратиками. Не использовать; неразрывный пробел U+00A0 — можно.
- Типограф библиотеки превращает « – » с пробелами в « — ». Диапазоны пиши слитно: «апр–июль», «2006–2011».
- Видео — только через `common.js` (`video`): тот же файл (mp4 или avi) и обложка из source.pptx, пропорции и обрезка кадра как в исходнике. Проверка байтов: `python3 tools/deck_check.py <deck> --source work/brands/<brand>/source.pptx`.
- Скрытые слайды исходника скрываем (`s.s.hidden = true`). LibreOffice их не рендерит — смотри через `python3 tools/deck_render.py <deck>`.
- Картинка во весь слайд часто лежит поверх старой версии слайда живым текстом: переносим видимое, расхождения — в отчёт.
- Шкалы столбчатых графиков — от нуля.
- Ручные переносы `\n` и неразрывные пробелы в русских строках английская сборка игнорирует при поиске перевода — их можно добавлять после перевода; любые изменения слов — нельзя без перевода новой строки (см. tools/en_missing.py).
- Цифры клиента не исправляем молча: явная опечатка — исправить и указать в отчёте; несходящиеся цифры — оставить как в исходнике и указать в отчёте.

## Ограничения

Пишешь только свой `decks/brands/<brand>/part_X.js`. Не трогаешь `lib/`, `DESIGN.md`, чужие файлы. Рендеры — только свои (`out/render/brand_<brand>_part_X/`).

## Отчёт (коротко, по-русски)

Файл, число слайдов; по каждому слайду — что сделано с композицией (было → стало); что исправлено в тексте (точно); ошибки и странности исходника; что вызывает сомнение.
