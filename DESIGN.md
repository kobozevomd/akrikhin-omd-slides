# Дизайн-система слайдов «Акрихин × OMD»

Источник: Figma «INT Акрихин Продакшн», страница «Слайды Акрихин» (15 слайдов 1920×1080).
https://www.figma.com/design/ewVvtyVRMvRixm05coFyFt/?node-id=1393-87
Эталонные рендеры всех 15 слайдов: `reference/figma_slide_01…15.png`.

Выход — редактируемый PowerPoint. Сборка кодом: `lib/akrikhin.js` (pptxgenjs).

## Формат

- Слайд 20 × 11.25 дюйма = 1920 × 1080 px фигмы. 1 px = 1/96 дюйма.
- Все координаты в коде — в пикселях фигмы. Кегль: **pt = px × 0.75** (47 px → 35 pt, 16 px → 12 pt).
- Шрифт **Tahoma** Regular / Bold, везде. Стрелки «→ ← ↑ ↓» и галочки в Tahoma нет — библиотека ставит их Arial отдельным раном.
- Без теней, без градиентов (кроме фоновых картинок обложки и шапки), без декоративных линий под заголовками.

## Сетка

- Поля слева/справа **58 px** (контент 58…1862).
- Шапка **0…187**: синяя полоса + угловой знак «a» (1441…1920). Заголовок слева от 58, ширина до ~1380.
- Контентная зона **221…905**.
- Плашка-вывод **935…1019** (высота 84, радиус 25), по центру.
- Сноска **1030…1050**.
- Колонки: 5 × 342 через 23 · 6 × 286 через 17 · 3 × 586 через 22 · 2 колонки ~880/900. Хелпер `columns(n, {gap})`.
- Карточка: радиус 25, обводка 3 px `line`. Внутренние блоки и плитки: радиус 15. Внутренний отступ карточки 27–39 px.
- В соседних колонках одинаковые элементы стоят **на одной высоте** (метка, заголовок, плитка, «что это меняет»).

## Компоненты (`lib/akrikhin.js`)

```js
const { Deck, C, ACCENTS, columns } = require('../lib/akrikhin');
const d = new Deck({ title: 'Название деки' });
d.cover({ title, logo: 'akrikhin_omd' | 'akrikhin', note });   // обложка
d.divider({ kicker: 'Раздел 2', title });                      // разделитель (производный, в фигме нет)
const s = d.slide({ title, subtitle });                        // контентный; subtitle → шапка с подзаголовком
await d.save('out/имя.pptx');                                 // + постобработка, тема, предупреждения о переполнении
```

| `s.badge({x,y,d,n,color,textColor})` | кружок с номером (84 / 70 / 46 / 38) | все |
| `s.box({x,y,w,h,fill,stroke,r})` | заливной блок / белая вложенная карточка | 7, 8, 9 |
| `s.stat({x,y,w,value,unit,label,color})` | плитка с большой цифрой | 2 |
| `s.tile({x,y,w,h,color,text,icon})` | цветная плитка с капс-текстом и иконкой | 4, 6 |

| `s.hline / s.vline` | разделитель `line` 1.5 px | 3, 7, 15 |
| `s.circle({x,y,d,fill,stroke,sw})` | круг / кольцо (большие цифры в кругах) | — |
| `s.chart(kind, series, {x,y,w,h,stacked,percent,format,legend,colors,...})` | живой график PowerPoint: `col`, `bar`, `line`, `area`, `pie`, `doughnut` | — (черновики Market Trends) |
| `s.table(rows, {x,y,w,colW,rowH,size,header,zebra})` | нативная таблица: шапка navy, обводки `line` | 15, 47 |
| `s.footnote(text)` | сноска | 7 |

Разметка в тексте: `**жирный**`, `[[акцент малиновым]]`, вложение `[[**жирный акцент**]]`, `\n` — перенос строки, `\n\n` — новый абзац.
Текст с `fit: true` сам уменьшает кегль до `minSize`, чтобы влезть в `h` / `maxLines` и не рвать длинные слова.
Всё, что не влезло, печатается предупреждением при `save()` — их нужно разобрать до выдачи.

## Графики

- Только живые графики PowerPoint (`s.chart`), данные — из исходника. Картинкой — только то, чего PowerPoint не умеет.
- Цвета серий по порядку `CHART_COLORS`: blue, crimson, cyan, green, purple, orange, navy, teal (проверено на различимость для дальтоников). Одна серия — один цвет (blue).
- Одна ось значений. Вторую ось (например, «динамика %» поверх столбцов) не делаем: проценты — подписями или отдельным мини-графиком.
- Подписи значений включены, ось значений и сетка скрыты, подписи и легенда — цветами текста, не цветом серии. Легенда — только при ≥ 2 сериях.
- График живёт в карточке (`card`) с КАПС-меткой над ним (`label`), источник — сноской внизу.

### Приёмы для слайдов с данными (эталон — `decks/variants/`)

- Одна история — один акцент: главное малиновым или синим, фоновые серии — приглушённым `A9BFD9`.
- Подписи прямо на графике (у концов линий, у столбцов) вместо легенды; свои подписи осей вместо стандартных (`catAxisHidden`).
- Справа колонка 452 px с 1–3 большими цифрами-выводами (`statTile`) или комментарием; номера-метки связывают комментарий с местом на графике.
- Производные цифры (п.п., «в N раз», доли, вклад в рост) — считаем в коде из данных и помечаем в сноске «расчёт OMD».
- Точная геометрия: `s.chart(..., { plot, min, max })` возвращает преобразование «данные → px» для подписей, линий среднего, заливок периодов; `chartMap` — то же до рисования графика.
- Общие помощники — `decks/variants/common.js`.

## Правила вёрстки

1. Шапка: без подзаголовка — до 2 строк (47 px); с подзаголовком — заголовок в 1 строку (41) + подзаголовок до 2 строк (29); если заголовок не влезает в 1 строку, `d.slide` сам переключается на «заголовок в 2 строки (37) + подзаголовок (25)» — эталон фигмы 12. Подзаголовок в тело слайда не выносим.
2. Одна мысль на слайд, вывод — в плашке внизу. Плашка — 1–2 строки, не больше.
3. Заголовки колонок — капсом; цвет метки = цвет номера колонки.
4. Текст выравниваем влево. По центру — только обложка, плашка-формула и пилюли.
5. Смешение RU/EN допустимо, как в эталоне; термины не переводим (CJM, AI DSP, SERP).
6. Иконки — белые линейные внутри цветных плиток/плашек. Фирменные из фигмы в приоритете, иначе Tabler (`tb:`).
7. Цифры с единицами — через `stat({ value, unit })`, единица мельче.
8. Если контента больше, чем помещается без сжатия ниже минимумов, — режем текст или делим на два слайда, предупредив Романа.

## Процесс: как оформляю присланный слайд

1. Читаю исходник: `markitdown файл.pptx` + рендер черновика (`tools/render.sh`), чтобы видеть структуру.
2. Выбираю архетип из таблицы выше; текст не переписываю по смыслу, только раскладываю (сокращаю — только с согласия).
3. Пишу сборщик `decks/<имя>.js` (копия `decks/_template.js`), собираю: `node decks/<имя>.js`.
4. Проверяю: предупреждения при сборке → `python3 tools/validate_pptx.py out/<имя>.pptx` → `tools/render.sh out/<имя>.pptx` → смотрю каждый слайд; при сомнениях сравниваю с эталоном `python3 tools/compare.py`.
5. Отдаю `.pptx` в папку `Преза/` с понятным именем.

## Технические заметки

- pptxgenjs пишет `<a:pPr>` перед каждым раном — `lib/postprocess.js` оставляет только первый (иначе PowerPoint может «восстанавливать» файл); там же стиль заголовка в мастере (Tahoma Bold 35 pt, белый).
- Кегль и интерлиньяж заголовков задаются на слайде: в плейсхолдерах макетов их нет намеренно (pptxgenjs иначе перебивает подобранный кегль).
- Макеты в PowerPoint: `AKR_COVER`, `AKR_SECTION`, `AKR_TITLE`, `AKR_TITLE_SUB`, `AKR_TITLE2_SUB`, `AKR_BLANK` — шапка и знак «a» живут в макете, их не надо копировать.
- Тема PowerPoint содержит фирменные цвета (accent1…6 = blue, crimson, cyan, green, purple, orange), так что палитра в PowerPoint сразу правильная.
- Предпросмотр через LibreOffice приблизителен (переносы могут отличаться на слово). Финальную проверку лучше делать в PowerPoint.
- Иконки рендерятся в PNG 256 px и кешируются в `.cache/`.
- PowerPoint переносит слова по дефису («риск-/тезисы»). Неразрывного дефиса (U+2011) в Tahoma нет, поэтому при таком переносе ставим ручной `\n` перед словом.
- Заголовки в 2 строки балансируются автоматически (`balanceTitle`): перенос там, где строки примерно равны, предлог не висит в конце строки. Ручной `\n` в заголовке отключает балансировку.
- Скрытый текст черновика (под карточками, за краем слайда) не переносим.
- Слайды без нижней плашки в черновике (данные Market Trends): контент занимает 221…1005, плашку не придумываем.

## Стратегии брендов: RU + EN из одной сборки

Серия дек «стратегия бренда 2027» (Акрихин × OMD). Каждая дека пересобирается в этой системе и выпускается на двух языках.

1. **Выгрузка исходника:** `work/brands/<brand>/source.pptx` → `python3 tools/extract_deck.py work/brands/<brand>/source.pptx work/brands/<brand>/src` + рендер исходника в `src/slide-NN.png`.
2. **Вёрстка:** `decks/brands/<brand>/brand.json` (`name`, `file`, `slides`) и `part_*.js` по брифу `work/brands/BRAND_BRIEF.md`. Проверка части: `node decks/brands/build.js <brand> --part part_a`.
3. **RU:** `node decks/brands/build.js <brand>` → `<outDir>/<file>_RU.pptx` (`local.json`, по умолчанию `output/`). Сверка текста: `python3 tools/word_diff.py <source.pptx> <ru.pptx>`.
4. **Строки для перевода:** `node decks/brands/build.js <brand> --record` → `work/brands/<brand>/strings_ru.json`; `python3 work/brands/tr_tools.py split <brand> 4`.
5. **Перевод:** переводчики по `work/brands/TRANSLATOR_BRIEF.md` (стайлгайд `STYLE_GUIDE_EN.md`, общий глоссарий серии `glossary_en.md`) → `tr/out_K.json`; редактор по `EDITOR_BRIEF.md` → `tr/edits.json`; `python3 work/brands/tr_tools.py merge <brand>` → `en.json`.
6. **EN:** `node decks/brands/build.js <brand> --lang en` → `<outDir>/<file>_EN.pptx`. Все строки проходят через `setTranslator` библиотеки до разметки и измерений, поэтому кегли и переносы пересчитываются под английский; числа (3,44 → 3.44) переводятся автоматически. Строки без перевода печатаются в конце сборки.
7. **Проверка EN:** `RENDER_LOCALE=en-US tools/render.sh …` (точки в числах графиков, как у англоязычного клиента).

Правило для part-файлов: каждая фраза — одной строкой целиком (словарь перевода ищет строку целиком), без склейки русских кусков шаблонами; геометрия не завязана на длину русского текста (`fit`, `maxLines`, высоты из возвращаемых значений).

Дополнения (Clindovit, 19.10.2026):
- Слайды-картинки исходника (сгенерированные макеты) пересобираются живым текстом: текст читается с картинки по увеличенным фрагментам, фото людей вырезаются в `work/brands/<brand>/src/crops/`. Особенности деки — в `work/brands/<brand>/TASK.md`.
